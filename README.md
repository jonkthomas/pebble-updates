# Meerkat updates

**Keep your coding limits in view.** Meerkat shows AI coding usage limits and reset times in your Mac's menu bar, with optional notch and low-limit alerts. Providers expose different data—percentages, time windows or credits—not always exact token counts.

Choose your coding profiles and press **Connect**. Claude, Codex and Grok read limits through their own coding apps; Muse shares its last observed report when supported. Claude uses native quota metadata, and connecting does not rewrite your status line. If a cold CLI has no limits yet, the separate **Probe usage** action sends one tiny Haiku prompt on a confirmed Claude subscription, then reads the real metadata in that same process. Each probe uses your Claude allowance and any enabled extra usage. Periodic checks and Connect/Retry send no model prompt. The separate **Probe missing Claude usage at startup** option defaults off: after explicit opt-in, Meerkat checks normally first, then may send one tiny fallback turn per connected, tracked Claude profile per app launch when supported native limits are genuinely missing or every returned window has already reset. You can turn it off during the check; an already-sent turn may finish. Authentication, malformed, unsupported and transport errors do not trigger automatic probes. A window with a reset time stays until that reset. A window with no reset time lasts 15 minutes (in memory; restarting discards it and the opted-in startup fallback may obtain a new one). API-key accounts are not eligible. A recent already-installed Claude reporter can remain a fallback. Native Claude usage support depends on your Claude Code version and account; unavailable limits remain unknown, never a guessed percentage. Pi, OpenCode and desktop clients can use the provider profile you explicitly select—not an invented extra quota. Meerkat does not import Claude login tokens or grant blanket Keychain or browser access.

Kimi Code and GLM optionally use keys you paste into Meerkat, stored in its own Keychain items. Kimi Code reads 5-hour, weekly and monthly usage limits from the key's issuing region; Meerkat never reads the Kimi CLI's sign-in. With the Kimi Code CLI installed and no key saved, **Kimi Code** connects in one click: Meerkat starts its own short-lived `kimi web` on this Mac only, asks it for the plan quota once, shuts it down, and shows 5-hour, weekly, monthly and monthly Code usage with its source (Kimi Code CLI or API key). Sign in with `kimi` in a terminal first, then add Kimi Code or press **Retry**; a pasted key always wins. Meerkat never reads the CLI's credentials, never opens a browser sign-in, and never sends a prompt. Every add step (nickname, GLM key, Kimi key) now has Back, and Escape goes back one step. Antigravity reads the model-free usage report from `agy` 1.1.11 or newer. Run `agy` in a terminal and sign in with Google first, then add Antigravity or press **Retry** in Meerkat. Background checks cannot open browser sign-in through the CLI's browser launchers. Missing usage stays unknown.

The overview leads with limits: the header counts accounts almost out, at their limit, signed out or unknown ("All under limit" only when every known limit is clear), rows say **Limit reached · resets 12:43 PM** and **Signed out · sign in**, one reset phrase is used everywhere, and resets more than six days away show their date. A row shows **Connect** only while it has no limits reading; otherwise Connect is in the row's menu. Closing the welcome guide is "finish later": Meerkat says **Finish setup** with **Resume**, and step 1 offers **Skip guide**.

In **Connections**, choose **Remove from Meerkat**, then **Stop watching**, to stop tracking a profile (the same question as the row menu's Remove). Its coding-app account, credentials and settings stay intact. **Disconnect** pauses readings without removing the profile. Adding a removed native profile back requires **Connect** again.

When a Meerkat release is available, download its **Meerkat DMG** from [Releases](https://github.com/jonkthomas/pebble-updates/releases), open it, and drag Meerkat to Applications. Release downloads are signed and notarized for macOS 14 or later on Apple silicon. The ZIP is for automatic updates.

Quit your installed copy before a manual replacement. Replace that copy rather than keep two apps. The technical app identity stays stable so existing accounts, settings and updates remain connected.

Updates download in the background and install when you quit, or when you choose Restart. `appcast.xml` is a signed Sparkle feed; do not edit it after signing. The public update repository and feed address stay stable for existing installs. Application source is not published here.
